   → 应急解法（已启用）：override 里给 VPS-ChatGPT 加 "dialer-proxy": "VPS-Hop"，流量经机场出国再连 VPS
4. "VPN 正常但 ChatGPT TLS 握手挂死"（2026-10-28）= dialer-proxy 跳板到不了 VPS。
   机场节点到 VPS 可达性不均匀且实时波动。已改专用 VPS-Hop 组与主选择组解耦。
   换跳板：MI_PIPE=<当前管道> node .diag-mihomo.cjs switch <节点名> VPS-Hop
   管道名以 `wmic process where "name='mihomo.exe'" get CommandLine` 的 -ext-ctl-pipe 为准。
5. 重装系统后 Reality 认证失败但服务端自环通过（2026-11-11）= 机场节点→VPS 链路对 Reality
   握手的干扰（已知波动现象），服务端与客户端参数均正确。等待/轮换跳板节点即可恢复。
   自环测试法（杀手锏）：在服务器上跑 xray 客户端配置连 127.0.0.1:443，curl --socks5 验证。
   深夜定性升级：干扰为协议无关逐连接随机（443/8443 Reality、443 httpupgrade 全中招），系机场
   反二级代理措施（本 IP 在代理黑名单）。8443 部分规避（true 窗口 2-3 成、波次性）；根治=换 IP
   （KiwiVM 免费迁移）或换机场。
6. KiwiVM 网页 Root shell 传长内容会丢字符：分条短命令 + base64 分段 + md5sum 校验；

   被截断成怪命令（如 "ray: command not found"）——发命令后必须验证回显与效果。
